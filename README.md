# 拼好图 · pinhaotu

> **三张图当一张图修，拼出一张好图片。**

像素蛋糕是按「张」算额度的，人像修一张就是一份钱。拼好图的办法很朴素：

先把 N 张照片严丝合缝地拼成**一张**画布，让它们只花一次额度；精修完再按记录
一刀一刀切回去 —— 每张都还是**原始像素**，一个像素都不差。

省下来的是额度，留下的是画质。这就是它存在的全部意义。

> 本仓库是 **Windows 版**：纯 Python + Pillow，双击 `启动.bat` 就能跑，
> 不用装 Electron、不用编译 native 模块。

---

## 快速开始

**双击 `启动.bat`**（首次运行自动安装 Pillow）。

---

## 使用流程

```
① 拖入照片  →  顶部选相机机型（或让它自动识别）
② 点「自动排版」     → 算出最少画布数 + 显示「省几次」
③ 点「全部导出」     → TILE_xxx_c01.tif + .manifest.json
④ .tif 导入像素蛋糕 → 只做调色 → 导出 TIFF（别改文件名）
⑤ 选回导出的 tif    → 点「③ 一键切回原图」
```

## 排版规则（修人像必读）

这一节是这个工具的核心，也是唯一需要你理解的地方。

### 1. 朝向优先 —— 人脸必须朝上

**默认零旋转**。竖屏照片竖着排、横屏照片横着排，摆进画布时保持原始朝向，
所以人物的脸永远是正的，像素蛋糕的人脸识别不会失效。

### 2. 密度靠「横竖混排」，不靠旋转

同一台机身的照片窄边相同、长边相同，竖图和横图的占位恰好互补，
混着排比清一色排得更满：

| A7M4（7008×4672 / 4672×7008），上限 12000、保护带 12 | 单画布张数 |
|---|---|
| 全横 | 2 |
| 全竖 | 2 |
| **横竖混排** | **3** |

3 张的摆法：竖图立成左窄列（宽 4696），横图叠成右宽列（宽 7032，两张高 9392），
总宽 4696 + 7032 = 11728 ≤ 12000。**一张都没转，人脸全正。**

> 不同机身结论不同：A7R（7952×5304）横竖互拼都超 12000，单画布只能 2 张。
> 顶部会按当前机型实时显示竖 / 横 / 混排各能放几张。

### 3. 保护带

每张图四周（含四个角）铺 12px 自身镜像。拼缝处像素连续，
精修时的液化位移场不会跨缝拉扯，切回来才不串味。

**不要设 0** —— 设 0 等于让所有照片的液化互相污染。

### 4. 「允许旋转 90°」开关默认关闭

关：所有照片保持真实朝向（竖图竖排、横图横排）。
开：排版器会按需把**个别**照片转 90° 塞进窄列换密度 —— 代价是那几张**人脸侧躺、
人脸识别可能失效**。**修人像不要开。**

`row` / `col` 版式**永远不旋转**，哪怕这个开关是开的 —— 一字排开的照片必须张张人脸朝上。

## 关键规则（违反会毁图）

| | |
|---|---|
| ✅ **可以做** | 曝光、对比、高光阴影、白平衡、色温、曲线、HSL、分离色调、纯色彩类预设、滤镜 |
| ❌ **绝对不要** | 液化、脸型、瘦身、身材、AI 换背景、AI 天空、AI 消除、AI 扩图、换装、证件照排版 |
| ❌ **不要裁剪** | 改变宽高比 → 切回直接拒绝 |
| ❌ **不要开排版印刷** | 同上 |
| ❌ **不要改文件名** | 靠文件名配对 manifest |
| ✅ **导出选 TIFF** | 唯一能无损往返的格式 |

**为什么禁液化 / AI**：几何变形 + 生成式重绘，拆开后像素不可逆，人脸 / 肤色也会被整画布统计污染。
**为什么允许调色**：曝光 / 白平衡 / 曲线是**逐像素静态映射**，拆回来各自带走，跨缝不污染。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| 画布单边上限 | 12000 | **13000 是导入硬闸门**：超过直接弹「图片尺寸过大」被拒，连静默降采样都不会发生。12000 与官方素材链路一致，留 1000px 余量 |
| 保护带 (px) | 12 | 每张图四边四角铺自身镜像。**不要设 0** |
| 间隙 (px) | 0 | 纯视觉分隔，不影响精度 |
| 允许旋转 90° | **关** | 见上文第 4 条。修人像请勿开 |
| 版式 | grid | grid = 自动装箱（朝向感知）；row / col = 单行 / 单列 |

> **三级上限**：`13000` 导入硬闸门 → `12000` 推荐值（默认）→ `16384` GPU 纹理上限。
> 16384 超了只是悄悄降分辨率，不是导入门 —— **别拿它当上限用**。
>
> **另外两条硬限制**：单边 `<100px` 或文件 `>1GB` 同样拒收。排版时过小的画布会直接报错；
> 导出后超过 1GB 的画布会在日志里橙色告警（画布单边上限输入框也锁在 13000 以内）。

## 输出

```
拼好图导出/
  TILE_a1b2c3d4e5_c01.tif              ← LZW 无损画布
  TILE_a1b2c3d4e5_c01.manifest.json    ← 切分唯一依据（绝对矩形 + 源 sha256 + 内嵌 EXIF）
  切回原图/
    shot1.jpg
    shot2.jpg
```

`.manifest.json` 里内嵌了每张图的 EXIF（`exifB64`），所以**原图归档或移走后照样能写回拍摄信息**。
别删它 —— 它同时是切分的唯一依据。

## 验证

```bash
python tiler_core.py            # 排版 / 合成 / 切回 自检，逐像素偏差必须 = 0
python tests/e2e_test.py        # 全链路（含模拟精修、缩放、裁剪拒绝）
python tests/_ui_shots.py       # UI 冒烟 + 截图（存到 tests/_shots/）
```

实测结果：

| 项目 | 结果 |
|---|---|
| 原样切回 | 全局最大像素偏差 **= 0** |
| 调色后切回 | 结构相关 **0.99984**（几何零漂移） |
| 导出被缩放 75% | 按比例映射 + 告警 |
| 宽高比被改（裁剪） | **直接拒绝** |
| A7M4 5 张混排（3 横 2 竖，不旋转） | 2 张画布，填充 89.2% / 79.4% |
| A7M4 12 张混排（6 横 6 竖，不旋转） | 5 张画布 = 数学最优 |
| A7M4 单画布容量（12000 / 保护带 12） | 全横 2 / 全竖 2 / **混排 3** |
| EXIF 往返 | JPEG 走 APP1 整段搬运；TIFF / PNG 走 Pillow 通道 |

## 已知边界

1. **画布上的脸是整张图一起做统计的**，建议同一场拍摄、同一光线。
   软件会把每张画布的**拍摄时间跨度**显示在副标题，跨度超阈值变橙告警；
   照片列表也带「拍摄」列，可一键按时间排序。
2. 保护带约占 2% 面积（画布边缘那圈镜像条）。
3. 一张 10000×10000 的 LZW TIFF 约 30–80 MB。
4. **HEIC / RAW 不支持**，先转 JPG / TIFF。
5. 合成是串行贴图，峰值内存 ≈ 画布 + 一张源图。
6. **切回格式选 TIFF 时 EXIF 会不全**：Pillow 的 TIFF 编码器写不了 ExifIFD 子目录，
   光圈 / 快门 / ISO / 镜头带不出（方向 / 机型 / 拍摄时间可以），
   切回报告的 `warnings` 会明确告知。要完整 EXIF 请选 **JPEG 或 PNG** 输出。
7. **row / col 版式混排时会留白**：尺寸不同的照片，较窄/较矮的一侧填背景色。
   这是为了保证切回是原像素 —— **绝不缩放**。同机型同朝向的照片不会有留白。
